## 4. 阶段输入：确实不是"同一任务两次"

`run_api_experiment.py` 的实际逻辑：

```python
stage = min((turn - 1) // a.stage_turns, len(tasks) - 1)
```

`stage_turns` 默认 2，所以每阶段是 **任务 → 请继续**，不是同一目标发两遍。论文 3.1 节的描述与实现不符，你的判断成立。

## 5. 五步上限：成立，而且比你说的更严重

代码 `while step < 5`，第 5 步若仍有 tool call，只把工具结果写回消息、退出循环，不再请求最终响应。

我从 64 份 JSONL 独立统计（与你的数完全一致）：

|---|---|

### 5.1 敏感性分析：核心结论会变

把 285 个截断轮次剔除后重算（3,840 → 3,555 轮）：

| 项 | 全样本 | 剔除截断 |
|---|---|---|
| `calls` regime | −0.7819, p = .0001 | −0.7206, p = .0005 |
| `calls` persona×regime | −0.7858, p = .0086 | −0.5831, p = .040 |
| **`calls` 三阶交互** | **+0.8683, p = .055** | **+1.0969, p = .0080** |
| **`zero_tool` 三阶交互** | **−1.0875, p = .098** | **−1.4931, p = .0145** |
| 会话级 `calls` regime | F = 56.50, p = 4.8×10⁻¹⁰ | F = 20.35, p = 3.4×10⁻⁵ |
| 会话级 `zero_ratio` regime | F = 36.64, p = 1.2×10⁻⁷ | F = 20.04, p = 3.8×10⁻⁵ |

**剔除截断后，轮级三阶交互从"边缘不显著"变成"显著"。**

这不是说论文的结论反了，而是说：**"阴性交互是结论"这句话对缺失机制敏感，不稳健**。截断集中在逆境（尤其 MiMo B-ni），属于信息性缺失（informative censoring）：它同时压低了逆境组的调用数与步数，把模型间差异抹平了一部分。

正确的做法不是二选一，而是：
1. 把 5 步上限写成设计的一部分；
2. 报告受影响轮次（285 / 3,840 = 7.4%）；
3. 主分析用全样本，同时报告剔除后的敏感性；
4. 若要一句话结论，只能说"在每轮最多 5 步的实现下，未检出稳定的三阶交互"，不能说"不存在"。
