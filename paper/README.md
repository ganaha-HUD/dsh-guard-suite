## 投稿定位

这是一份 **empirical report（经验报告）**，不是因果论文。标题里保留了 "Preliminary Case Study"，
这是故意的：它降低了审稿人对因果强度的预期，也给你大二做对照实验留了升级空间。

**可以投的地方**（由易到难）：

1. **arXiv**（cs.CL 或 cs.SE）—— 最快，有 timestamp，能占位。需要 PDF + 摘要页。
2. **Workshop**（如 NeurIPS/ICLR 的 workshop）—— 对 preliminary work 友好，审稿周期短。
3. **正式期刊/会议** —— 建议等做完 A/B 对照实验再投。

## 投稿前必须检查的三件事

**① GitHub 链接是否是活的**

正文第 8 节指向 `https://github.com/ganaha-HUD/dsh-guard-suite`，但那个仓库目前只有插件代码，
**数据集和论文还没上传**。投稿前二选一：

- 把 `collapse-dataset/` 和 `paper/` 推到同一个仓库；
- 或者新建 `dsh-collapse-dataset` 仓库，然后把正文里的链接改掉。

链接是死的，审稿人第一条就会问。

**② 中文版不要投**

中文版是给你自己看的。arXiv 和英文期刊只收英文。中文版可以作为博客/知乎/B 站的配套发布。

**③ 作者署名与单位**

`report-v1.md` 顶部写的是 `ganaha-HUD`。投稿时要换成真实姓名和单位（大一可以写学院）。
arXiv 需要作者邮箱和 ORCID（可选）。

## 这篇报告的卖点（投稿信里可以这么说）

1. **现象新**：现有退化研究几乎都讲"膨胀"（重复、变长），这篇讲"收缩"（变短、变空、语气不变）。
2. **统计上有反思**：step 级和 turn 级给出相反量级的效应量，作者主动披露并解释了原因
 （离散变量中位数饱和 + 伪重复）。这一点审稿人会喜欢，因为它显示作者知道自己在做什么。
3. **可复现**：全量标注、标注代码、原始日志、复现脚本都在。
4. **有前兆指标**：suspect → collapse 的转化率（20 轮内 94.4% vs 基线 44.4%）可以直接用于监控。

## 已知弱点（审稿人一定会问，先想好怎么答）

| 问题 | 怎么答 |
|---|---|
| 只有一条轨迹 | 承认。这是存在性证明，不是发生率研究。下一阶段做 A/B。 |
| 人格和时间混淆 | 承认。已在 CONFOUNDERS 里逐条列出，并给出控制方案。 |
| 没有标注者间一致性 | 承认。下一步找第二个人独立标 10%。 |
| "坍缩"的判定是启发式 | 承认。规则是公开的、可执行的，别人可以改阈值重跑。 |
| 为什么不用现成的重复检测器 | 用了，它 0 次触发。这恰恰是发现的一部分。 |
